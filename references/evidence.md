# 怎样记录来源，区分证据和推测

写论文笔记时，最重要的是让后来阅读的人能够查清：这句话来自哪里，实际核对过什么，又有哪些部分是你的解释。这份说明约定文献记录的身份、来源和核实状态。实验结论如何判断，另见 [研究与实验记录说明](science.md)。

## 先确认是不是同一篇论文

记录使用 `schema_version: 2`，这个数字与软件发布版本分别管理。标题便于阅读和查找，不能代替稳定标识。

以下身份需要分别保存，不能互相替代：

- DOI 和 arXiv 版本：说明是哪篇论文、哪个版本。
- `library_id`：说明属于哪个 Zotero 文献库。
- `zotero_key`：论文主条目的 key。
- `pdf_key`：具体 PDF 附件的 key。

用户指定了 key，就在指定的文献库中精确查找。遇到身份冲突，保留冲突信息并停止处理这一项，不能拿标题最接近的第一条记录代替。

Skills 中的资源链接相对仓库填写，研究记录中的路径相对 Vault 填写。真实 Vault 必须明确配置在代码仓库之外。只有示例和测试数据，才可以显式启用 synthetic 模式并放在仓库内。

## 不同文件分别记录什么？

PDF 是论文的原始来源。Fulltext 保存原始提取文本或来源缓存，并记录提取过程；Paper Note 是对一篇论文的阅读和分析；Knowledge 则整理多篇笔记，同时保留它们之间的分歧。

整理得再清楚的 Knowledge 页面，也不能补足缺失的原始来源。

对每项重要主张，使用下列标签说明核实到哪一步。标签本身保留英文，方便软件读取。

| 标签 | 读者可以据此理解什么 |
| --- | --- |
| `pdf_verified` | 已对照身份明确的 PDF 核查这句话。 |
| `fulltext_verified` | 已在身份明确的提取文本中核查；文本提取本身的限制仍然存在。 |
| `note_supported` | 有链接的 Paper Note 支持这句话，并且能继续查到它的来源。 |
| `derived` | 依据已引用的输入，按明确步骤计算或推导得到。 |
| `interpretation` | 这是阅读者的分析，原文没有直接确立这个结论。 |
| `speculative` | 这是等待证据的解释或研究方向。 |
| `unverified` | 所需证据尚未检查，或材料缺失。 |

页面整体的标签只是概况，不能让其中尚无依据的主张一并变成“已核实”。尽可能记录来源位置、Note 路径、Fulltext 路径和附件身份。材料缺失时填 `null` 或明确的缺失原因：记录不完整可以接受，没有来源却声称已经核实则不可以。

## 引文、数字和图表怎样记录？

引文必须来自实际可访问的原文，并附来源位置。页码要实际核对，不能根据 PDF 阅读器的文件页序猜测论文页码。

重要数字要同时保留单位、分母、研究对象或总体、实验条件和不确定性。如果数字来自计算，还要写出输入和计算过程。

没有读过的表格或图片就标为未读。不能根据前后文看起来合理，就补出其中的内容。

## 更新笔记时，保留哪些东西？

先精确确认身份，再复用已有记录。Fulltext 保留原始文本，不能用摘要替换。更新已有页面时给出 diff，让研究者看清改动；未在本次修改范围内的用户内容保持原样。

重要主张或结果可以额外保存来源快照，记录输入文件等信息。但普通 Concept 页面不需要为了形式完整，另外创建哈希记录文件。

所有引用路径都应指向正确的记录层。重要 Knowledge 主张的来源应能沿着真实 Note，继续查到论文主条目的 key、Fulltext 和 PDF 附件。只在网上找到的论文，不能编造成本地来源链接；在获取并检查前，它仍是候选文献。

## 为什么不把 Fulltext 当普通笔记改写？

提取文本可能包含公式、引文或看起来像 Markdown 链接的字符。这些属于原始内容，并不是用户编写的 Vault 链接。

验证器检查 Fulltext 的结构化来源指针、附件身份、与 Note 的双向链接，以及来源和文本摘要值。正文中的链接检查用于人工编写的 Note 等记录，不应要求原始提取文本也符合这种写法。

不要为了消除链接检查错误而改动原文。历史试验发生在 Vault 之外时，可以把当时的路径作为来源信息保存，但不能伪装成当前可访问的 Vault 链接。

## 验证通过后，可以说明什么？

报告中要说清搜索过什么、读过什么、提取了什么，以及哪些问题还没有解决。

结构验证能发现缺失链接、身份不一致和不允许的状态，不能证明科学结论正确、人工审核完成或文献覆盖完整。上面的文献标签，也不同于实验结论使用的 `SUPPORTED`、`NOT_SUPPORTED`、`INCONCLUSIVE` 和 `NOT_TESTED`。

示例数据只能验证示例流程，不能当作真实论文的评测结果。
